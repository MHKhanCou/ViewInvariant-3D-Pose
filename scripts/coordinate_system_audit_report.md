## 1. MotionAGFormer Output Convention

### Model output
- Input: 2D keypoints in normalized screen coordinates [B, T, 17, 3]
  - x, y are pixel coordinates normalized to ~[-1, 1]
  - 3rd channel is confidence score
- Output: 3D joint positions [B, T, 17, 3]
  - x, y, z are predicted 3D coordinates
- Training uses `root_rel=True`: ground truth has root subtracted
- Model predicts root-relative 3D poses (root at origin)

### camera_to_world() in demo/vis.py
```python
rot = [0.1407056450843811, -0.1500701755285263, -0.755240797996521, 0.6223280429840088]
post_out = camera_to_world(post_out, R=rot, t=0)
post_out[:, 2] -= np.min(post_out[:, 2])  # shift z to non-negative
post_out /= max_value  # normalize to [0, 1]
```

### Role of camera_to_world()
- Applies a FIXED quaternion rotation (same for all frames)
- Transforms from model output coordinates to a display-friendly orientation
- This is VISUALIZATION ONLY — it does not recover real-world coordinates
- The quaternion is hardcoded, not calibrated to any specific camera
- No translation is applied (t=0)

### For cross-view evaluation
- Model output is root-relative 3D (root at origin)
- camera_to_world() is NOT used for evaluation
- Cross-view comparison should use raw model output or canonical form
- Camera-coordinate transforms (if needed) come from MPI-INF-3DHP calibration, not from camera_to_world()

### Coordinate Transform Convention
```
Extrinsic matrix E = [R | t; 0 1]

To transform world coordinates to camera coordinates:
  P_camera = E @ P_world

To transform camera coordinates to world coordinates:
  P_world = inv(E) @ P_camera
```

### For cross-view evaluation
1. annot3[i] gives 3D joints in camera i's coordinate system
2. To compare camera 0 and camera 1 predictions:
   - Option A: Transform both to a shared world frame using inv(E)
   - Option B: Transform camera 1's predictions to camera 0's frame: P_cam0 = E0 @ inv(E1) @ P_cam1
3. The choice depends on whether we want world-frame or camera-frame comparison

## 6. Coordinate Transform Pipeline

### Step-by-step for cross-view comparison

```
1. Load annot3 for camera A and camera B
   → P_A: 3D joints in camera A's coordinate system
   → P_B: 3D joints in camera B's coordinate system

2. Load camera extrinsics E_A and E_B (4×4 matrices)
   → E transforms world → camera: P_cam = E @ P_world
   → Inverse transforms camera → world: P_world = inv(E) @ P_cam

3. Transform both to shared world frame:
   P_world_A = inv(E_A) @ P_A
   P_world_B = inv(E_B) @ P_B

4. Alternatively, transform B to A's frame:
   P_cam0_from_B = E_A @ inv(E_B) @ P_B

5. Compare aligned predictions:
   - Joint positions should match (within model error)
   - Bone lengths should be identical
   - Joint angles should match
```

### Important notes
- annot3 is in PER-CAMERA coordinates — not a shared world frame
- Camera extrinsics provide the transform between world and camera frames
- The 'universal' normalization (univ_annot3) does NOT provide a shared frame — it only applies minor scale adjustments
- For cross-view evaluation, we MUST use camera extrinsics to align predictions

### MotionAGFormer prediction alignment
- MotionAGFormer predicts root-relative 3D (root at origin)
- The 2D input is in screen coordinates (pixels)
- The 3D output is in a model-internal coordinate system
- For cross-view comparison, we need to:
  1. Run YOLOv8-pose on each camera's RGB
  2. Run MotionAGFormer on each camera's 2D keypoints
  3. The output is root-relative — we need to add back the root position
     from the 2D-to-3D lifting (or use annot3's root position)
  4. Transform to shared coordinates using camera extrinsics
  5. Compare canonical vs raw predictions
